# BALI Academy

Единая GitHub-backed система обучения персонала BALI без отдельной базы данных.

## Что входит

- `admin-desktop/` — ПК-приложение администратора (Electron, Windows).
- `ios-staff/` — единое iOS-приложение персонала (SwiftUI): после входа открывает внутреннюю часть **Бармен** или **Официант**.
- `sync-gateway/` — stateless serverless gateway. Он хранит данные только в GitHub, но не отдаёт GitHub write-token мобильному приложению.
- `content/` — меню, знания, коктейли, алиасы, уроки и тесты.
- `data/` — создаётся автоматически gateway: зашифрованные профили сотрудников и результаты тестирования.

## Логика входа персонала

На новом устройстве сотрудник:

1. вводит ФИО;
2. выбирает `БАРМЕН` или `ОФИЦИАНТ`;
3. получает стабильный персональный профиль, вычисляемый из нормализованных ФИО + роли;
4. дальнейшие результаты тестирования синхронизируются в GitHub через gateway;
5. администратор видит историю сотрудника с любого устройства.

> Текущий UX специально соответствует требованию «ФИО + должность». Это идентификация, а не сильная аутентификация. Для более строгого доступа следующим уровнем можно добавить PIN сотрудника или подтверждение нового устройства администратором.

## Разделение ролей

### Бармен

Видит:

- продукт и происхождение;
- историю/стиль/вкус;
- подачу и стекло;
- коктейли;
- матчасть и техники;
- продажи и AI-тренера;
- тесты и собственный прогресс.

**Цены бармену не показываются.**

### Официант

Видит:

- всё меню;
- актуальные цены;
- наличие;
- краткие знания по алкоголю;
- подачу;
- сервис;
- психологию продаж и ethical upsell;
- тесты и собственный прогресс.

## Администратор

Windows-приложение показывает:

- всех сотрудников;
- фильтр `Бармен / Официант`;
- количество подключённых устройств;
- число попыток;
- средний и лучший результат;
- показатели по категориям;
- слабые вопросы;
- **полную историю каждой попытки**;
- ответы сотрудника и правильные ответы по ошибкам;
- единый редактор контента с публикацией обратно в GitHub.

## AI-тренер

AI работает только через server-side gateway и получает role-aware контекст BALI.

Режимы:

- `Спросить`;
- `Объяснить`;
- `Продажи`;
- `Проверить`.

Поиск сущностей поддерживает:

- русский язык;
- английский язык;
- транслит;
- распространённые опечатки;
- заранее заданные aliases;
- fuzzy matching по edit distance.

Примеры:

- `макалан`, `маккалан`, `macalan`, `Macallan`;
- `лонг айленд`, `лонгайленд`, `long iland`, `Long Island`;
- `егермейстер`, `Jagermeister`.

Если найдено несколько достаточно похожих сущностей, AI **не угадывает молча**, а возвращает выбор из нескольких вариантов.

## Контент

### `content/menu.csv`

Операционный каталог и цены. Это удобный слой для частых правок.

### `content/knowledge.json`

- category defaults;
- расширенные карточки;
- aliases;
- уроки;
- тесты;
- базовые учебные коктейли;
- настройки тестирования.

### `content/cocktails-extra.json`

Дополнительный каталог коктейлей/алиасов, включая Long Island Iced Tea.

### `content/bundle.json`

Опциональный compiled override. Когда администратор публикует контент из ПК-приложения, gateway может записать полный bundle. При его наличии он имеет приоритет над split-files.

## Безопасность GitHub-хранилища

Репозиторий может быть публичным, поэтому персональные данные не записываются открытым JSON.

Gateway использует:

- HMAC-ID для имени файла сотрудника;
- AES-256-GCM для содержимого профиля;
- AES-256-GCM для истории результатов;
- HMAC-signed staff session tokens;
- отдельный `ADMIN_API_KEY` для админских методов;
- GitHub token только на сервере.

В iOS-приложении **нет GitHub write-token**.

## 1. Развернуть gateway

Каталог: `sync-gateway/`.

Подходит Vercel serverless deployment.

Задайте переменные окружения по примеру `sync-gateway/.env.example`:

```text
GITHUB_TOKEN=...
GITHUB_REPO=Nik13599/BALI-Academy
GITHUB_BRANCH=main
ID_SECRET=...
DATA_ENCRYPTION_KEY=...
SESSION_SECRET=...
ADMIN_API_KEY=...
OPENAI_API_KEY=...
OPENAI_MODEL=gpt-5.6
```

### GitHub token

Токен gateway должен иметь доступ только к нужному репозиторию и минимально необходимое разрешение на чтение/запись Contents.

Секреты никогда не добавлять в репозиторий.

## 2. Собрать iOS

Для проекта используется XcodeGen.

На macOS:

```bash
cd ios-staff
xcodegen generate
open BALIStaff.xcodeproj
```

Перед сборкой замените в `project.yml`:

```yaml
INFOPLIST_KEY_BALI_GATEWAY_URL: https://YOUR-GATEWAY.vercel.app
```

на адрес развернутого gateway.

Далее в Xcode:

1. выбрать Team;
2. проверить Bundle ID;
3. запустить на iPhone;
4. для распространения использовать обычный Apple signing/TestFlight/Ad Hoc процесс.

## 3. Запустить Windows Admin

```bash
cd admin-desktop
npm install
npm start
```

Для `.exe`/NSIS installer:

```bash
npm run dist:win
```

При первом запуске открыть **Настройки** и указать:

- Gateway URL;
- тот же `ADMIN_API_KEY`, который задан на gateway.

Ключ сохраняется локально через Electron `safeStorage`.

## 4. Тестирование

Тренировочный режим:

- случайный порядок вопросов;
- случайный порядок вариантов;
- 10/20/30/50/100 вопросов;
- фильтр категории;
- уровни 1–5 или смешанный;
- неправильный ответ сразу фиксируется как ошибка;
- показывается правильный вариант и объяснение;
- исправить текущий результат задним числом нельзя;
- пересдача не ограничена;
- каждая завершённая попытка синхронизируется админу.

## Рабочие техкарты коктейлей

Коктейли в starter-content помечены как **учебная классика** (`trainingRecipe: true`, `operationalRecipe: false`).

После добавления утверждённых техкарт BALI именно они должны стать рабочим источником рецептуры. Учебная классика не должна самовольно заменять внутреннюю техкарту клуба.

## Что хранит GitHub

```text
content/
  menu.csv
  knowledge.json
  cocktails-extra.json
  bundle.json               # появляется после admin publish, если используется

data/
  employees/<opaque-id>.json  # encrypted
  results/<opaque-id>.json    # encrypted
```

`data/` создаётся автоматически при первом использовании.
